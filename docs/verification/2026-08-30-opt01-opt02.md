## 失败→修复→通过证据

1. 自动发现/退出码/空运行保护：先增加6个 Python 行为测试；旧 runner 不支持来源目录/发现模式，6项失败。实现发现和运行保护后6项通过。
2. 真实 Java 回归首次运行：`Tests run: 34, Failures: 3`、退出1。失败为缺 `org.springframework.mock.web.MockMultipartFile` / `MockHttpServletRequest`，不是业务断言失败。`spring-test` 是测试作用域、不在应用 fat jar；补其现有6.1.2依赖后12类36项通过。
3. 旧字节码保护：补第7个行为测试，旧实现错误地退出0，断言失败；增加源/字节码时间比较后全部7项入口测试通过。
4. 独立评审发现 Python 原生 discover 在空套件时仍退出0；新增4个 Python runner 行为测试，缺少入口时均失败。引入小型标准库 runner，检查非空、失败和 skipped 后，全部13个活跃本地测试通过。未增加第三方依赖。
5. 同一评审指出 Node 的应用 engines 范围不能保证支持 TypeScript 测试。新增数据库初始化前的 `node-test-runtime` 检查，实测 `node --experimental-strip-types --eval 'console.log(process.version)'` 退出0并输出 v24.18.0；没有自动升级 Node，也未声称旧版本支持该测试入口。
