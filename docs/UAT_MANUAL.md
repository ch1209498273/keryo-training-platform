# 初学者人工 UAT 操作手册

> 目标：让没有系统测试经验的项目负责人，可以按照步骤完成 V1.0 Portfolio Release 的人工验收。
>
> 本手册只描述如何操作和记录，不代表任何用例已经通过。当前 Manual UAT 状态为 **NOT STARTED**。2026-08-19 的 `BUG-UAT-001～010` 是开发回归后的 `FIXED` 记录，不能代替本手册中的原发现人/项目负责人复测。

## 0. 使用规则

### 0.1 测试环境

1. 使用本地或内网 Demo 环境，不使用正式业务库，不在系统 MySQL 3306 业务数据上做破坏性操作。
2. 使用项目现有启动入口启动前后端，例如 `启动服务器.bat` 或 `scripts/start_all.sh`。
3. 浏览器访问前端地址，默认是 `http://localhost:8000`；如果启动脚本显示了其他端口，以启动脚本输出为准。
4. Baseline 的临时数据库和端口只用于自动验证，运行结束后会清理，不能作为人工 UAT 的长期环境。
5. 新建的培训、计划和考试名称统一使用：`UAT-日期-姓名缩写-业务名称`，避免和别人测试的数据混淆。

### 0.2 Demo 账号

以下账号只用于隔离 Demo/UAT 环境。若当前环境密码不同，以项目负责人实际创建的 Demo 账号为准，并在结果记录中注明。

| 账号           | 密码           | 角色                                | 主要用途              |
| ------------ | ------------ | --------------------------------- | ----------------- |
| `admin`      | `<本地管理员密码>`   | 超级管理员                             | 系统配置、审批、全量业务查看    |
| `nurse_head` | `<本地管理员密码>`   | 培训管理员/医护总监（代码角色 `keryo_director`） | 培训、计划、考试和成绩管理     |
| `student`    | `<本地学员密码>` | 学员（`keryo_nurse`）                 | 学习培训、参加考试、查看结果    |
| `team_lead1` | `<本地学员密码>` | 小组长（`keryo_team_leader`）          | 学员功能和本人范围内的计划参与管理 |

每次登录都必须填写图形验证码。看不清时点击验证码图片刷新，不要关闭验证码校验。

### 0.3 FAIL 时必须保存的证据

任何一步失败，不要只写“不能用”。在 `docs/UAT_BUG_LEDGER.md` 新建一个 Bug 编号，并记录：

- 截图或录屏；
- 页面名称、浏览器地址和当前角色；
- 从哪一步开始、每一步具体点击了什么；
- 输入的数据和数据名称；
- 页面提示、接口提示或浏览器控制台提示；
- 发生时间；
- 是否刷新后仍然发生、是否可以稳定复现；
- 对业务的影响；
- 是否阻断后续流程。

未完成证据记录前，不要直接修改代码或数据库。

## UAT-001：登录、验证码和退出

**测试目的**
确认用户可以正常登录，验证码始终显示且错误验证码不能绕过登录。

**测试角色**
`admin`，随后使用 `student`。

**前置条件**
服务已启动，浏览器能打开前端登录页。

**操作步骤**

1. 打开 `http://localhost:8000`，确认登录页同时显示账号、密码和图形验证码。
2. 输入 `admin`、`<本地管理员密码>`，故意输入错误的验证码，点击登录。
3. 确认仍停留在登录页，再点击验证码图片刷新。
4. 输入新验证码并再次登录。
5. 进入系统后点击右上角用户菜单，点击退出登录。
6. 使用 `student` / `<本地学员密码>` 重复登录并退出。

**预期结果**

- 登录页始终有验证码；
- 错误验证码不能登录；
- 正确账号、密码和验证码可以进入对应角色首页；
- 退出后回到登录页，不能继续使用已退出会话。

## UAT-002：管理员菜单和基础权限

**测试目的**
确认管理员能看到系统管理功能，普通学员不会因为知道页面地址而获得管理员菜单或权限。

**测试角色**
`admin`、`student`。

**前置条件**
已完成 UAT-001，并能分别登录两个账号。

**操作步骤**

1. 使用 `admin` 登录，查看左侧菜单，确认能看到系统设置、组织架构、用户/角色/菜单等管理员功能。

- `admin` 能访问管理员菜单；
- `student` 不显示管理员菜单；

**实际结果**

PASS / FAIL

## UAT-003：培训资料创建和维护

**测试目的**
确认培训管理员可以创建真实培训资料，并能打开预览或维护资料信息。

**测试角色**
`nurse_head`。

**前置条件**
准备项目空间中的真实 PDF/PPTX/DOCX 文件；不要上传密码、Token 或个人敏感文件。

**操作步骤**

1. 登录 `nurse_head`。
2. 打开【培训管理】页面，点击【添加】或【新建】。
3. 标题填写 `UAT-日期-姓名缩写-培训资料`，选择一个真实培训文件并上传。
4. 填写页面要求的其他必填项，点击保存。
5. 在列表中搜索刚才的标题，打开详情或预览。
6. 将标题末尾增加 `-已维护`，保存后刷新列表。

**预期结果**

- 文件上传成功并出现在培训列表；
- 详情中的标题、文件类型和文件内容正确；
- 预览页面能打开，或系统明确提示当前文件预览方式；
- 修改后的标题刷新后仍然保留。

**实际结果**
填写：

**结果**
PASS / FAIL

**如果 FAIL**

## UAT-004：培训计划、考试关联、提交和审批

**测试目的**
确认培训管理员可以创建计划、关联培训和考试并提交，管理员可以审批计划。

**测试角色**
先用 `nurse_head`，再用 `admin`。

**前置条件**
已完成 UAT-003；系统中有可选择的已发布考试。优先使用现有演示考试，或使用专门创建的 UAT 考试。

**操作步骤**

1. 使用 `nurse_head` 打开【培训计划】→【新建】。
2. 填写标题 `UAT-日期-姓名缩写-计划`、说明和有效起止时间。
3. 选择 UAT-003 创建的培训资料。
4. 选择一个可用考试，确认考试名称显示在计划中。
5. 保存计划，记录计划名称或 ID。
6. 点击【提交】或【提交审批】，确认状态从草稿变为待审批。
7. 退出并使用 `admin` 登录，打开【培训计划】。
8. 找到该计划，打开详情，确认培训和考试关联正确，点击【审批通过】。

**预期结果**

- 计划能保存并显示关联培训、关联考试；
- 提交后进入待审批状态；
- `admin` 能看到并审批；
- 审批通过后计划进入可用/进行中状态。

**实际结果**
填写：

**结果**
PASS / FAIL

**如果 FAIL**

**实际结果**

**结果**
PASS / FAIL

## UAT-009：Golden Path 完整业务闭环

**测试目的**
从真实用户视角完整走通“准备培训 → 分配人员 → 学习 → 考试 → 结果复核”，证明系统不是只有单接口通过。

**测试角色**
`nurse_head`、`admin`、`student`。

**前置条件**
使用一组全新的 UAT 标识；准备真实培训文件和可用考试；不要使用已交卷且次数耗尽的考试。

**操作步骤**

1. `nurse_head` 登录，创建或维护一份带 UAT 标识的真实培训资料。
2. `nurse_head` 创建培训计划，绑定该培训资料和可用考试，保存并提交审批。
3. `admin` 登录，审批该计划通过。
4. `admin` 或 `nurse_head` 进入计划，分配 `student`。
5. `student` 登录，打开【培训】，进入并浏览培训资料。
6. `student` 从培训卡片或【考试中心】进入关联考试。
7. `student` 答题并交卷，确认生成考试记录。
8. `student` 打开考试记录，记录成绩是否已公布。
9. `nurse_head` 或 `admin` 查看该学员的考试结果和计划参与情况。
10. 管理人员按当前业务规则公布成绩（如果本次 UAT 需要验证公示）。
11. `student` 退出并重新登录，确认仍能看到正确的培训/考试结果。
12. 将计划 ID、培训 ID、考试 ID、参与账号、考试记录 ID 写入 UAT 结果。

**预期结果**

- 上述 12 步均可完成；
- 角色之间看到的数据和操作按钮符合权限范围；
- 培训、计划、考试、参与关系、答卷、成绩之间可以相互追溯；
- 没有已知 P0 阻断。

**实际结果**
填写完整过程和 ID：

**结果**
PASS / FAIL

**如果 FAIL**
按失败发生的第一步建立 Bug，不要只记录最后页面的错误。

## UAT-012：重复提交和考试次数限制

**测试目的**
确认一场考试交卷后不能被学员重复创建或重复提交，避免重复成绩和业务数据污染。

**测试角色**
`student`。

**前置条件**
使用一场专门的 UAT 考试；确保该账号有且只有一次可用机会。

**操作步骤**

1. 正常进入考试并交卷一次。
2. 在结果页点击浏览器刷新。
3. 返回【在线考试】，再次尝试进入同一考试。
4. 如果系统允许进入，观察是否提示已完成、次数用尽或需要补考；不要再次提交答案。
