# V1.0 安全与业务缺陷闭环规格

日期：2026-08-19  
状态：已获用户确认，开发修复与自动回归完成，等待人工 UAT RETEST  
范围：Portfolio Release V1.0 的 P0/P1 缺陷整改；不扩大到生产部署与灾备建设。

## 目标

在不改变现有 Spring Boot + Shiro + JWT + Vue 架构、且不修改数据库结构的前提下，修复交接审计中已确认的登录绕过、令牌校验、接口越权、考试资格和关键统计缺陷，并以可重复的负向测试和 UAT 台账证据闭环。

## 设计决策

### 1. 鉴权链保持单一入口

- 登录必须同时满足非空用户名、非空密码和有效图形验证码；空密码不得进入密码比较成功分支。
- 受保护请求先验证 JWT 签名和有效期，再解析 subject；禁止仅使用 `JWT.decode` 作为认证依据。
- JWT 密钥从 `keryo.security.jwt-secret`/环境变量注入。非开发环境缺失密钥时启动失败，Java 代码不再持有硬编码生产密钥。密钥变更会使旧令牌失效，需重新登录。
- refresh token 也必须验证签名、有效期、令牌类型、用户存在且处于可登录状态，并在换发后撤销旧令牌。
- Shiro/JWT 的匿名路由采用精确白名单；只有登录、验证码、刷新令牌及明确的静态资源可匿名访问。

### 2. 权限采用“控制器声明 + 服务层兜底”

- 管理端写操作补齐 `@RequiresPermissions`，读取操作至少要求认证。
- 关键资源在服务层再次校验角色、数据范围、资源归属和计划参与关系，避免绕过控制器直接调用。
- 学员端只允许访问本人和本人所属培训计划/考试数据；管理端不能通过修改 ID 绕过数据范围。

### 3. 业务规则在服务层闭环

- 试卷预检、创建和进入考试统一检查培训计划参与资格、状态、时间窗口和次数限制。
- 仪表盘通过率使用数值语义，未完成统计只计算当前计划参与者；数据范围为空的行为显式固定并有测试。
- 培训计划自动结束必须有可执行的定时触发或明确的调用入口，不能只保留孤立方法。

### 4. 安全边界和运维缺陷按 V1 能力处理

- 来源校验使用精确 origin 比较；CORS 不再使用凭据模式下的全开放来源。
- 验证码调试接口由显式配置控制，不能依赖方法级 profile 注解；默认关闭。
- 文件扩展名、MIME 和文件头校验保持一致，拒绝未支持或伪造类型。
- 密码找回/管理员改密失败必须返回失败，不吞异常后返回成功。

## 分批实施与验收

1. P0 鉴权：先写失败测试，再实现空密码、JWT 签名/密钥、refresh、TTL 和匿名路由修复。
2. P0 权限与资格：覆盖管理接口、资源归属、计划参与关系和考试直达接口。
3. P1 业务与边界：修复统计、自动结束、数据范围、来源/CORS、验证码调试和上传校验。
4. 证据闭环：运行后端单测、目标前端测试和静态检查；在 `docs/UAT_BUG_LEDGER.md` 记录每项“问题—修复—验证命令—结果”。

每一批的完成条件是：对应负向测试通过、既有回归测试通过、差异只涉及该批目标文件，并且台账有可复现证据。未具备运行环境的真实登录/UAT、生产数据库迁移、Docker/CI、灾备演练和备份介质清理不伪造为已完成，继续列为开放项。

## 风险与兼容性

- JWT 密钥外置后，密钥变更会让现有会话失效；这是预期的安全行为。
- 不新增表、不修改现有表结构、不执行生产数据库写操作。
- 工作区已有未提交修改不回退；实现前按文件记录基线，避免覆盖无关改动。
