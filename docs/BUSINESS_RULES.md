## 1. 用户角色与权限

系统共 8 个角色（`el_sys_role`），其中 `user` 已停用（保留数据，不授权）。实际使用 7 个：

| 角色 id | 名称 | data_scope | role_level | 学员端 | 核心权限 |
|---|---|---|---|---|---|
| admin | 超级管理员 | 4 全量 | 999 | ❌ | 系统配置（用户/角色/菜单/字典/AI设置）、备份 |
| keryo_director | 总监（医护总监） | 4 全量 | 100 | ❌ | 全量业务 + **成绩修正专属** + 成绩公示/补考 + 题库审核 |
| keryo_assistant | 助理管理员 | 4 全量 | 90 | ❌ | 业务大部分；**不能改成绩、不能公示** |
| keryo_supervisor | 区域督导 | 3 区域（area） | 80 | ❌ | 管辖区域业务 + 题库审核主力 |
| keryo_head_nurse | 医护长 | 2 本科室 | 60 | ✅ | 本科室成绩/计划/看板；不可建题/审核/公示 |
| keryo_nurse | 一线医护 | 1 本人 | 40 | ✅ | 学员端：培训/考试/个人设置 |
| keryo_team_leader | 小组长 | 1 本人 | 30 | ✅ | 学员端本人范围；可在本部门管理计划参与关系 |
| user | 学员（停用） | 1 | 1 | — | 废弃角色，注册默认已改为 keryo_nurse |

**数据范围嵌套**：本人(1) ⊂ 本科室(2) ⊂ 区域(3) ⊂ 全量(4)。

**用户决策（2026-08-07，已落地）**：
1. 一线医护 = keryo_nurse，user 角色删除/停用。
2. 医护长完全不碰题库（建/审都不行）。
3. 助理有管理员大部分权限，但不能改学员成绩；可建题，其题需督导审核。
4. 总护理长（妈妈）= 医护总监，有成绩修正仲裁权（专属 `exam:record:edit`）。
5. 督导按 area 映射，督导之间权限一致、数据互不可见。
6. **督导/总监/助理/超管不参加考试**（无学员端菜单）；医护长保留学员端（要考试）。
7. 新增「小组长」角色；学员端权限保持本人范围，并补充本部门计划参与关系管理能力。

## 2. 账号与注册

- 注册开关：`el_cfg_switch` USER_REG（管理端「个性配置」可开关）。
- 注册字段：userName / realName / password / 验证码。**userName 与 realName 后端强制非空**（2026-08-13 修复，此前仅前端拦截）。
- 注册默认角色：**keryo_nurse**（原默认 user 已停用，2026-08-13 修复）。
- 注册成功 → 跳转登录页（不再自动登录进系统）。
- **密码规则（全系统统一，reg/update/pass/reset 通用）**：只允许字母+数字、必须同时包含字母和数字、长度 ≤30、不允许特殊字符。`SysUserServiceImpl.validatePassword()`。

## 3. 忘记密码流程（T-18，2026-08-13）

**方案：管理员审核重置**（用户决策，因姓名是弱凭证、系统无短信服务）：
```
学员：账号 + 真实姓名 + 图形验证码 → 提交申请
  → 后端校验：验证码正确 + 账号存在 + 姓名与账号匹配 → 写 el_keryo_forget_pass 记录(status=0)
  → 提示"申请已提交，请等待管理员处理"
管理员：组织架构 → 忘记密码申请 → 查看（账号/姓名/状态/时间）→ 标记已处理（可填备注）
  → 在「用户管理→编辑→登录密码」给学员重置密码
```
- `reset-pass` 自助重置接口已下线；忘记密码仅提交申请，由管理员审核后处理。
- 申请记录权限：`sys:user:forget-paging` / `sys:user:forget-handle`，授权 admin + keryo_head_nurse。

## 4. 培训内容（原课件，T-13 更名）

- 课件概念已全链路更名「培训」（表/包/接口/前端/菜单）。
- 培训内容 CRUD + 上传（PPTX/DOCX/PDF），Office Online Viewer 预览 PPTX/DOCX、PDF.js 预览 PDF。
- 上传文件 MIME + 扩展名 + 魔术字节校验（H4）。

## 5. 培训计划（T-06.3 / T-13）

- 状态机：`DRAFT →(提交)→ PENDING →(审批通过)→ ACTIVE →(到期)→ ENDED →(归档)→ ARCHIVED`
- 一个培训计划关联一个培训内容（`courseware_id`，T-13b 决策）。
- 计划可关联考试（`exam_id`）。
- **学员参与**：管理员在计划里分配学员（`el_keryo_plan_user`）；只有被分配的学员才在学员端看到该计划的培训/考试。
- 列表过滤不是授权边界：培训详情/预览/下载、考试详情和试卷预检/创建均在服务层重复校验参与关系与计划状态。
- 演示计划：`t13_demo_plan`（ACTIVE，已按 BK-04/BK-05 关联真实血液透析培训和演示考试；历史占位数据已处理）。

## 6. 题库与题目

- 题目类型（全小写）：`radio`单选 / `multi`多选 / `judge`判断 / `fill`填空 / `essay`简答。
- 两级审核状态机：`DRAFT →(一审)→ REVIEW2 →(二审)→ APPROVED / REJECTED`
  - **不可审自己**（createBy 校验）；一/二审不可同人（firstReviewer）。
- **只取 APPROVED 题目**：随机练习已删；考试组卷 `listForPaper()` 按「题库+题型」随机抽 APPROVED 题目。
- **考试组卷不绑定培训主题**：从所选题库按题型随机抽题（这导致演示题库脏题会被抽中，见 KNOWN_ISSUES）。
- 审核权限点：`repo:qu:add` / `repo:qu:edit`（医护长无）。
- 题库分类：数据字典 `repo_catalog`，当前 3 个分类：**职业技能 / 培养管理 / 其他**（2026-08-13 用户要求精简）。
- AI 出题：DeepSeek 生成 → 人工审核 → 入库；AI 失败降级人工出题（不卡核心）。

## 7. 考试（T-05 / T-14 / T-15）

- 考试参数：总分 / 及格分 / 考试时长 / 可考次数 chance / 交卷时限 / 迟到时限。
- **补考（T-14）**：考试默认只允许一次（演示考试 chance=1）；交卷后不能再次考试；如需重考由管理员在成绩管理发起「补考」（`exam:record:retry` 重置 tryCount，保留历史成绩，补考后按新成绩更新最近分/通过）。
- **成绩公示（T-15）**：`el_exam.score_visible`（0=不公示/1=公示）。
  - 未公示：学员交卷结果页/考试记录页显示「成绩待管理员公布」，明细分数掩码。
  - 管理端考试列表【公布成绩/收回】随时切换（`exam:exam:edit`）。
  - 后端 `/paper/detail`、`/full-detail` 对学员掩码（管理角色放行），直接调接口也拿不到。
  - 演示考试 score_visible=0（默认不公示）。
- 判分：radio/multi/judge/fill 自动判分；**essay 人工阅卷**（管理端考试详情带 `isAdmin=1` 参数显示阅卷框，`/api/exam/paper/qu/review-essay`，阅卷后自动重算总分+同步 record）。
- 考试中隐藏主观题参考答案（detailForAnswer 对 fill/essay 清空 answerList）；阅卷页 fullDetail 才返回标准答案。
- 防切屏（T-05.3）：前端 visibilitychange/blur + 后端 IP 变更检测(IP_CHANGE) + 单题<2秒检测(FAST_ANSWER) + 切屏计数标黄/标红；不强制交卷。
- 作弊记录表 `el_exam_cheat_log`，管理端可查看。

## 8. 成绩与统计

- 成绩修正：`exam:record:edit` **仅总监**（妈妈专属仲裁权），修改 max_score/last_score/passed + 写审计日志。
- 成绩查看/导出：按 data_scope 过滤（督导=区域、医护长=科室、医护=本人）。
- 学分系统已删除（T-16）：不再发放/统计学分，企业培训看「当次合格 + 参训次数」。
- 统计看板（T-10）：通过率折线 + 参训/未完成名单 + 仪表盘卡片，按 data_scope，权限 `keryo:stat:overview`。

## 9. AI 配置（T-17）

- 管理端「系统设置 → AI 设置」（仅 admin，`sys:ai-config:view/edit`）。
- 供应商模板：deepseek / qwen / openai / kimi / zhipu / custom，切换自动填 base_url + model。
- **api_key 存数据库** `el_keryo_ai_config`，管理端查看时脱敏（只显示掩码），保存时留空不覆盖。
- `/test` 接口测试连接。AI Key 不写入 yml；运行时优先读取 `AI_<PROVIDER>_API_KEY`，其次读取 `AI_API_KEY`，数据库 Key 仅作为兼容回退。

## 10. 审计与安全规则

- 审计日志 AOP：`@AuditLog` 写 `el_keryo_audit_log`，PII 脱敏（姓名仅留姓、手机号中间4位****、IP 末段脱敏）。BK-08 提供只读管理端查看页，按账号/姓名/模块/结果/时间检索；审计表禁止删除。
- 密码存储：bcrypt（cost≥10，已测试）。
- 登录失败锁定：`LoginProtectionService`（≥N 次失败触发锁定/验证码）。
- 品牌强约束：全量替换「云帆」→「医护培训平台」，代码层已清零；种子数据已替换（残留仅外部 CDN 图片）。
