## 1. 结论与推荐路线

**适合采用，但应采用手册“存量迭代变体”，不能整套照搬。**

本项目仍以 **V1.0 Portfolio Release** 为目标：真实业务背景、完整培训考试闭环、可复核工程证据、人工验收和可演示交付。不是重做一个 AI 原生产品，也不是建设正式医疗生产平台。

最有价值的补充是：任务契约、业务验收口径、AI 内容依据、失败与人工兜底、效果评测、版本与证据管理。当前最缺的不是 Agent 或更多页面，而是证明“已有功能确实按业务预期工作”的完整链条。

| 可选路线 | 收益与代价 | 结论 |
|---|---|---|
| 全量套用 SOP，补知识图谱、RAG、多模型路由、运营看板 | 范围大，依赖新的数据、预算和业务人员；推迟人工验收 | 不推荐 |
| 沿用当前里程碑，补核心验收，再补已存在 AI 功能的最小可靠性与评测 | 保持 Baseline，成果可验证，适合当前资源与作品集目标 | **推荐** |
| 暂停 AI 展示，仅交付培训考试主链路 | 若 AI 质量/预算/审核条件不足，可作为发布降级方案 | 保留；不可静默删除已承诺能力 |

两件事必须区分：**AI-assisted 工程实践**是项目开发方法；**产品内 AI 出题**是一项可选辅助能力。证明前者不要求把产品改造成自主 Agent。

推荐顺序：**证据与测试入口对齐 → 核心 UAT/复测 → 业务与内容回验 → AI 最小补强及评测 → Demo/发布**。沿用 M1.5～M2，不新增平行里程碑。

## 4. 实际缺口：代码事实与待验证风险

以下证据位置相对仓库根目录，行号以本次工作区为准。静态路径可确认，但用户可见故障、发生频率和数据库状态仍需相应运行验证。

### G-01 — 测试证据没有完整汇入统一入口

- `scripts/baseline/run_java_tests.ps1:46` 附近仅显式运行 3 个 Java 测试类；`scripts/run_unit_tests.sh:53` 起列出 12 个。
- `scripts/baseline/run_baseline.ps1:295` 以 `package -DskipTests` 打包，随后调用前述独立 Java runner；不能据此称全部现有 Java 测试都已执行。
- `scripts/baseline/smoke.py:103` 起创建试卷、加载答题卡后直接交卷；没有提交具体选项并断言得分，也没有覆盖 AI 内容质量、两级审核、简答阅卷完整链路。
- 另有前端会话/模型模板测试、本地 Python 启动器测试；需要标明各自命令及是否进入门禁，不与已归档套件混淆。
- **影响：**“Baseline PASS”有明确覆盖范围，不能自动证明后续新增修复或答题判分正确。

### G-02 — “根据培训内容出题”实际上没有读取培训正文

- `yf-bev2-vue/src/views/Training/Training.vue:226` 请求只发送 `coursewareTitle`、手填 `topic` 等；空 topic 回退标题。
- `yf-bev2-api/src/main/java/com/yf/modules/exam/repo/controller/RepoQuController.java:229` 将这些文本直接传给生成服务。
- `yf-bev2-api/src/main/java/com/yf/modules/exam/repo/service/impl/AiQuService.java:334` 用标题/主题构造 Prompt，此链路不读取课件正文，也没有检索引用。
- **影响：**生成题可能与培训主题相近，但不能声称“依据已上传课件逐页出题”。
- **最小建议：**先准确标识“根据主题生成草稿，未自动读取附件”；展示实际送入模型的内容。若增加材料摘录输入，必须显式校验长度，不能沿用 500 字静默截断。自动解析整份文件另列可选任务。

### G-03 — AI 配置保存与停用缺少可靠闭环

- `yf-bev2-vue/src/views/System/AiConfig/AiConfig.vue` 的 `load()` 未将服务端返回的 `id` 保留到表单。
- `yf-bev2-api/src/main/java/com/keryo/training/modules/aiconfig/service/impl/AiConfigServiceImpl.java:99` 按请求 id 找配置；无 id 则新建。`getActiveConfig()` 只取任意一条 enabled=1。
- **静态风险：**连续保存可能累积配置，旧启用记录仍被选中；“Key 留空保持不变”依赖更新同一条记录，目前链路不保证。
- 没有启用记录时，`effectiveEndpoint()` 仍可能从环境变量取 Key；`viewConfig()` 无记录时返回 enabled=1。因此页面停用不等于已证明外部调用为零。
- UI 说明“Key 仅存在数据库”，与环境变量优先机制不符；“测试连接”测试已保存配置，不是尚未保存的表单。
- **最小建议：**明确单一有效配置、保存原 ID、停用优先于密钥来源；用本地假服务验证，不使用真实 Key。对旧模型参数的自动归一化增加可见说明/回归，不能把模板当成供应商兼容性保证。

### G-04 — 批量生成超时后，用户不知道已经保存了什么

- `AiQuService.java:227` 起逐题同步调用、逐题保存；`chat()` 单次请求超时为 60 秒。前端默认总请求超时也是 60 秒（`yf-bev2-vue/src/config/axios/config.ts:12`）。多题总耗时可能超过前端等待上限。
- `generateOne()` 的 `chat()` 在 JSON 解析 try 外；网络/供应商失败可直接中断批次。前面已保存的题不会因此自动撤销。
- 单题数量上限主要按每题型处理，不是统一批次预算；去重主要依赖 Prompt 中的 `usedStems`，不是稳定幂等机制。
- **影响：**页面报失败而已有部分 DRAFT 入库，用户再点可能重复生成/消费；这是静态可见失败路径，尚未实测发生次数。
- **最小建议：**先限定小批量与总预算，返回计划数/成功数/失败数/已保存题 ID，明确部分成功；以批次标识防止重复保存/盲目重试。如何在总超时内完成先测量再选择局部实现，不立即引入队列平台。

### G-05 — 结构合法、医学正确、教学可用被混在一起

- `AiQuService.java:178`、`:378` 的主要完整性校验为题干非空、答案列表非空；选项数量、重复项、正确项数量、题型与答案一致性仍需独立校验。
- 题型选择、格式校验、分值运算应由程序负责；医学依据和题目是否适合学员由有资质/相应专业能力的内容审核人评判。
- `generateAnswer()` 也属于 AI 内容入口，不能只测批量出题漏掉参考答案功能。
- `AiQuService.java:71` 和 `:185` 存在记录供应商原始错误体/模型原文的路径。使用真实材料前需检查脱敏与日志范围，不能因 Key 脱敏就认为内容不会泄露。
- 当前检查的 Java 测试目录没有 AI 配置或生成服务的对应测试；AI 模板前端测试不等于生成质量测试。

### G-06 — “必须不同人两级审核”存在代码例外

- `docs/BUSINESS_RULES.md` 第 6 节描述不可审自己、一二审不同人。
- `RepoQuServiceImpl.java:252`、`:278` 有 `isSuperReviewer()` 豁免；`:303` 起批量审核可直接 APPROVED；`:330` 的实际豁免角色包括超管、总监、督导。
- **这是文档与代码冲突，不直接判定哪边符合业务。** 不能擅自取消既有角色能力，也不能在作品集中宣称所有题都经过两个独立审核人。
- 现有 APPROVED 限制真实存在（`:193` 起）；AI 草稿不会因为生成成功自动 APPROVED。但它不证明所有 APPROVED 都完成相同审核过程。

### G-07 — 参训次数不等于完成学习，也不等于培训有效

- `PlanUser.java` 记录计划/用户/创建时间，不记录阅读进度或学习完成证据。
- `DashboardServiceImpl.java` 的 `annualTrainingCount()` 统计年度重叠计划的参与关系；`completedCount` 基于考试记录。当前学员预览操作本身不能证明学会。
- 必须区分：被分配人次、已交卷人数/人次、合格人数/比例、已阅读/完成学习。哪个作为“完成培训”仍需业务确认。
- 随机组卷按题库和题型抽 APPROVED，不按培训主题自动约束。优先用专用题库和内容映射保证 Demo 对题，不先造知识图谱。

### G-08 — 治理文档有过时表述，不能用来重复立项

- PROJECT_CONTEXT 仍称小组长额外管理不在范围，ROADMAP BK-14 与 BUSINESS_RULES 已记录本部门参与管理。
- 背景/业务/问题文档仍写 Office Online Viewer；当前 `Training/components/FilePreview.vue` 使用 docx-preview、pptx-preview 和浏览器 PDF，并被培训页面引用。是否渲染正常仍需 UAT，不是继续按旧公网预览风险扩建环境。
- Roadmap 一处称 M1.5 未开始，一处称 M1.6 修复完成；Ledger 与 Case Study 的开头状态也未完全同步。
- **建议：**保留历史记录，新增带日期的当前摘要、事实来源和待确认项，避免覆盖历史或全量重写资料。

## 6. 本项目要补的业务场景与内容

### 6.1 保留原 Golden Path，增加明确可验的结果

负责人维护经授权培训材料 → 制定学习目标 → 人工建题或 AI 草稿 → 按已确认规则审核 → 在所选题库配置考试 → 创建计划、关联培训与考试 → 分配人员、审批 → 学员查看材料 → 实际答题并交卷 → 必要的简答阅卷 → 成绩按公示规则可见 → 管理人员复核记录与统计。

AI 不可用时走人工建题/现有导入，不跳过审核；主链路不依赖真实 API Key。考试页“进入成功”和“交卷返回成功”不代替答案保存、判分、公示验收。

## 7. 轻量评测方案：把“技术可用”和“内容好用”分开

### 7.1 三张真实任务卡，不凑不存在的 Agent 能力

| 已有任务 | 输入/输出 | 确定性检查 | 人工责任与失败处理 |
|---|---|---|---|
| 生成参考答案 | 题型、题干 → 可编辑参考答案 | 输入长度、空响应、类型、权限、安全输出 | 审核人对照依据确认；失败保留原题，不自动替换正式答案 |
| 单题草稿 | 主题、题型、难度 → 表单草稿 | 所需字段、选项去重、正确项数量、题型对应关系 | 标注 AI 辅助；人工修订并走现有审核 |
| 批量草稿 | 内容依据/主题、题型数量分值、目标题库 → DRAFT 与批次结果 | 总数量/预算、目标权限、逐题校验、重复操作、成功/失败统计 | 部分成功可追踪；失败转人工，不把错误批次当空批次重做 |

### 7.2 样本、指标和门禁

建议先准备 **30 条探索性样本**：12 条正常任务（覆盖三个入口及已有题型）、6 条空白/乱码/格式错误、8 条权限/注入/敏感信息/依据冲突等风险场景、4 条历史或模拟故障（超时、限流、部分成功、重复提交）。这只是起始规模，不代表统计置信保证。历史真实 badcase 与人工设计样本分别标注。

- 样本在调 Prompt 前固定；保留未用于调试的验证子集，报告样本版本、分组和实际分母。重复生成次数与独立样本数分开。
- 先用 mock 验证 API/解析/权限/异常，无付费请求；真模型评测要有授权的材料和预算上限，不默认使用本机密钥。
- 格式通过率、依据充分性、医学正确性、教学适用性、无需修改/修改后采纳/拒绝、用时和费用分别统计。不用一个平均分掩盖风险。
- 格式校验失败的题不得保存；草稿不能自动 APPROVED；既定权限不得被提示词绕过；停用后不得继续外发。这些确定性安全不变量应在定义的测试集上全部通过。
- 展示用正式题目必须经过逐题人工审核。没有合适的专业审核人时，医学正确性写“未完成专业验证”，不能由 Agent 代签。
- 正常任务采纳率先记录现状，再决定改善目标；不直接复制手册的70%。小样本中不宣称总体“零事实错误”或上线99%可靠。
- 延迟分别记录登录、单题、整批。用户提出的登录3秒要求需按端到端登录结果测量，不能通过统一设置3秒请求超时“实现”；整批 AI 也不能沿用登录 SLA。
- 暂无 RAG/工具 Agent 的引用准确率、Tool Calling 正确率等指标记 **N/A**，不是 PASS。

### 7.3 最少需要保存的数据

评测文件可先用小型 CSV/JSONL，不建运营看板。字段建议：`case_id / source_type / input_version / prompt_version / model_id / params / run_time / result / error_category / reviewer / edit_category / latency_ms / usage / measured_cost / linked_bug / regression_result`。

成本定义：**该轮全部请求（含失败与重试）实际费用 ÷ 最终可采纳结果数**；采纳数为0时记“不适用/无可采纳结果”，不填0成本。另列人工审核分钟数；没数据不估造 ROI。没有 usage 或账单时标缺失，不把“连接成功”当计费证据。

Prompt 先随代码提交版本化，记录材料与模型配置版本；不强制热更新后台。Bug 仍进现有 Ledger，加 `AI` 分类和评测样本 ID，修复后补回归，不建第二套 Bug 系统。

这些是内容评价与建议，不修改用户原始手册。没有核查其引用书籍的原文，因此不评价引文真实性，也不把示例模型/价格当作最新供应商信息。

| 位置 / 问题 | 为什么不宜直接用 | 建议改法 |
|---|---|---|
| 总览“唯一推荐做法”“每个环节只有一个最优路径” | 项目阶段、风险和数据条件不同，不存在普适唯一流程 | 改为默认路线+适用条件+裁剪规则；保留不可削弱的安全/证据底线 |
| SOP-0 大量使用“给谁看报告”来定义需求 | 产品用户任务不等于领导汇报任务；拍板也不等于产品有价值 | 分开产品任务声明和汇报任务声明；以业务任务完成作为效果证据 |
| SOP-1 固定“模型→检索→规则→人工” | 本项目无检索链路；检索后改写仍可能生成错误 | 按失败类型设计；此项目优先保留输入、显示失败、人工建题/导入，不假造降级能力 |
| SOP-3 统一85%/99%/95%等门槛 | 缺少分母、任务风险、样本量与测量方法 | 作为示例，不作为通用硬标准；定义测试集与安全不变量，测量后定目标 |
| SOP-3/案例“安全题必须全部拒答” | 合法医学教学问题不能只因含禁忌等词就拒答；该拒绝的是越权、泄露、无依据编造等行为 | 逐例写允许动作、禁止动作和人工转交条件，不用关键词一刀切 |
| SOP-5 第422行成本例子 | A：0.1/0.6≈0.167元/成功；B：0.3/0.9≈0.333元/成功，仅给定数据并不支持“B更便宜” | B是否更划算需补人工审核/返工/失败损失等数据，不能偷换成本口径 |
| 案例第592行“每月30套×14中心=420套/年” | 单位错误且30套是总量还是每中心不清 | 若全平台30套/月则360套/年；若每中心30套/月则5040套/年 |
| 案例单题0.3元→每套50题≤0.5元→实测0.18元/套 | 前后基准差异巨大，无测量/参数变化说明 | 明确估算、目标、实测三种口径，统一单位；不能直接当预算依据 |
| 案例5分钟生成、响应<10秒、10秒超时 | 接受请求、首个结果、整批完成混为一谈；重试后总时长另算 | 分别定义用户反馈时间、单题/整批完成时间及总时限 |
| 案例“3天→4小时节约87%” | 未定义每天工作小时，无法复算；按8小时工作日为83.3%，按72小时自然时长为94.4% | 指明工时口径，保留原始观测，不从叙事倒推指标 |
| 案例指标、中心数量/人员规模/题量等 | 本轮未获得对应真实运行与业务证据，不能作为该项目事实 | 标注“教学示例/假设数据”；有原始证据再单独引用，不导入 Case Study 统计 |
| 案例“曲线跟着修复走，所以因果可验证”“评测分数永远更高”“日志造不了假” | 时间相关不证明因果；评测偏差方向不固定；日志也可能缺失/失真 | 报告证据强度、混杂因素和限制；日志需版本/范围/对照，不能绝对化 |
| SOP-4 强制灰度比例、生产看板、ROI红线、积分账 | 无正式运营用户/收入，不适合单人 Portfolio；积分体系已被项目决策删除 | 用受控 Demo 试用、开关、故障记录和人工验收代替；生产项留未来 |
| 职场妥协与免责表述 | 留痕不能代替安全控制或业务责任确认 | 可裁剪文档和流程成本，不能以赶进度为由泄露真实数据、越权或发布未经审核内容 |

## 10. 发布条件、确认点与下一步

### 发布条件

- 核心系统：冻结候选的干净 Baseline、现有活跃回归、人工 Golden Path、权限/异常 UAT 都有证据；没有已知 P0 或影响核心演示的 P1。
- AI 功能：另列“工程失败保护验证”和“内容/业务评测”结果。若未达标，不伪装成熟能力；是否作为受限实验功能展示由负责人确认，关闭它不能破坏核心培训考试。
- 部署：清晰启动和停止方式、可重复 Demo 数据准备、已知限制与回退方案。应用回退要核对数据库兼容性；不通过重建业务库“回滚”。
- 生产交付、CSP强制、复杂合规/基础设施仍不进入本次范围。MySQL观察独立记录，不伪造168小时稳定结论。

### 后续执行中确实需要业务确认的事项

1. “完成培训”是参加分配、阅读资料、交卷还是合格？若要证明学习时长/进度，需要另行需求定义，不能自动加签到系统。
2. 超管/总监/督导的自审、同人二审、一键审核是否为认可的例外？先核对既有批准记录，不默认推翻。
3. AI是作品集必须完整展示的能力，还是明确标注实验性的加分项？推荐在可靠性门禁通过后再展示。
4. 哪份材料可对外展示、谁负责专业内容审核？未确定前不发送真实敏感材料给外部模型。
5. 真模型效果评测如要开展，其费用上限是多少？本地 mock、文档整理与核心 UAT 不依赖这个决定。
